### 🚀 Highlights

- 🧩 Custom metadata for frps plugins: the Server tab now lists `[metadatas]` entries with add, edit and remove actions. Imported metadata is preserved instead of being rejected, and it is written back when the frpc config is generated, so plugin requirements such as an instance ID survive a round trip. In multi-user mode `token` stays in its dedicated field, and keys that look like credentials are masked by default with an explicit reveal control.
- 🏷️ Config export attribution: Export config now starts with a comment header containing the Frpc-Desktop version, copyright, project link and MIT license.
- 🫀 Safer heartbeat imports: TOML files and `frp://` links whose `heartbeatTimeout` is shorter than `heartbeatInterval` — a pair frpc rejects — are repaired on import by raising the timeout to the interval. Omitted values keep the 30s / 90s defaults before that check.
- 💾 Precise unsaved-change warnings: the configuration drawer compares the form with the last saved snapshot, so changing a value back no longer triggers the prompt. Edits made while a save is in flight still count as unsaved, as does a metadata draft that was typed but not added.
- 🩺 Cleaner import errors: unreadable or invalid TOML files show the actual reason in the UI, while the application log only records a stable code (B1000) so local paths and configuration contents stay out of `main.log`.

### 🐛 Bug Fixes

- Fixed imported `[metadatas]` tables being rejected as unsupported, which dropped metadata on the next save.
- Fixed `frp://` link imports producing an invalid heartbeat pair.
- Fixed the unsaved-changes dialog appearing after an edit was reverted to its saved value.
- Fixed a metadata draft being discarded without warning when the drawer closed.
- Fixed TOML read failures showing a generic error with no underlying reason.

### 🔄 Upgrading from 2.0.2

- Installs over the existing 2.0.2 app in place. Instances, proxies, server settings, desktop settings and downloaded frpc / cloudflared binaries are kept.
- No database schema changes in this release.
- Existing instances behave as before; their generated frpc config is unchanged unless `[metadatas]` entries exist.
- Exported configs now include a comment header, which frpc ignores.
- The Windows portable ZIP is still available.
