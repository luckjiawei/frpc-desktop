# 资源占用统计与 WebView 补全计划

本文面向维护资源统计功能的开发者，记录当前实现、统计边界，以及后续补全 WebView 占用的方向。

记录日期：2026-11-13。

## 1. 目标与当前状态

目标是显示当前 Frpc-Desktop 及其运行的隧道、WebView 等相关进程的 CPU 和内存占用。

当前已实现主进程及其后代进程的汇总，包括应用启动的 frpc、cloudflared 实例。macOS 中由系统服务托管的 WebKit 辅助进程尚未纳入，因此当前数据不能代表包含完整 WebView 的应用总占用。

WebView 统计补全处于待调研、待实现状态，尚未验证可靠的进程归属接口。

## 2. 当前实现

相关代码：

- [采样与进程树汇总](../src-tauri/src/system/usage.rs)：`AppUsageSampler`、`process_tree_pids`、`usage_from_totals`。
- [后台轮询与事件推送](../src-tauri/src/system/mod.rs)：`SystemService::start_usage_poller`。
- [前端状态与数值格式化](../src/store/systemUsage.ts)。
- [侧栏资源显示](../src/layout/compoenets/LeftMenu.vue)。

采样流程：

1. 使用 `std::process::id()` 获取当前应用的 PID，作为进程树根节点。
2. 使用 `sysinfo` 刷新系统进程列表及进程的 CPU、内存数据，按父 PID 建立子进程映射。
3. 从根节点遍历全部后代，按 PID 去重；过滤 Linux 单独暴露的线程条目，避免与所属进程重复计入。
4. 汇总相关进程的 CPU 和驻留内存。
5. 每 3 秒通过 `system:watchSystemUsage` 事件推送结果，前端更新侧栏。

启动时先采样一次建立 CPU 计数基准，等待 3 秒后才推送第一份结果。每轮重新构建进程树，并移除已退出的进程，以反映实例启动、停止和重启。

### CPU 口径

`sysinfo` 的单进程 CPU 使用率以占满一个逻辑核心为 100%，多线程进程可能超过 100%。界面按整机总算力归一化：

```text
显示 CPU 百分比 = 相关进程 CPU 使用率之和 / 逻辑核心数量
```

例如，8 个逻辑核心中合计占满 2 个，显示约 25%。最终数值限制在 0–100%。

### 内存口径

内存为相关进程驻留内存（RSS）之和。后端的 `memory.used` 以 MiB 为单位，前端沿用 MB/GB 标签显示；`memory.percentage` 为该合计占物理内存总量的比例。

共享内存页可能在多个进程中重复计入，因此该数值不等于应用独占物理内存，也不保证与系统任务管理工具采用的内存口径一致。

## 3. macOS WebView 的已知缺口

Tauri 在 macOS 上使用 WKWebView。网页渲染、JavaScript 执行，以及部分 GPU、网络工作由独立的 WebKit 辅助进程承担。

这些辅助进程可由系统服务启动，父 PID 不属于 Frpc-Desktop。当前仅根据父子关系遍历，所以会遗漏这部分占用。主进程中承载窗口及 WebView 的开销仍会计入，但不能据此认为已包含完整 WebView。

不能通过进程名匹配后累加系统里的全部 WebKit 进程，否则会把其他应用的占用计入。也不能只按启动时间接近来判断归属。

Windows、Linux 上的 WebView 辅助进程是否全部落在当前进程树中，也需要在对应平台验证，不能由 macOS 或单个平台的结果推断。

## 4. 后续实现方向

优先调研 macOS 是否存在适合当前应用使用、能可靠识别进程归属的接口，再确定最终方案。以下是候选方向，不代表接口可用性已经确认。

| 候选方向 | 预期覆盖 | 待确认事项 |
| --- | --- | --- |
| 获取当前 WebView 的渲染进程 PID | 网页渲染与 JavaScript 进程 | Tauri、WKWebView 是否提供可依赖的接口；进程重启或切换后如何更新 PID；GPU、网络进程仍可能遗漏 |
| 按系统提供的应用进程归属或进程组信息识别辅助进程 | 尽可能覆盖渲染、GPU、网络辅助进程 | 接口稳定性、权限、开发模式与安装包差异，以及共享辅助进程能否准确归属 |

优先评估第二种方向，使统计更接近整个应用的占用；如果只能可靠识别渲染进程，应明确说明仍未覆盖的部分。

实现时需要满足：

- 保留主进程及隧道进程树的现有统计，在此基础上补充有明确归属的 WebView 辅助进程。
- 所有来源的 PID 合并去重，避免某个平台上的 WebView 已属于进程树而被再次计入。
- 处理辅助进程退出、重启、PID 变化和 PID 复用，持续更新归属。
- 评估公开接口的可用性和兼容性；涉及私有接口时，先记录稳定性和分发限制，再决定是否采用。
- 归属查询失败或权限不足时，保留现有进程树统计，并明确其覆盖范围；不能把其他应用的进程当作回退结果。
- 保持现有 CPU 归一化和内存口径，避免补全进程范围时同时改变数值含义。

## 5. 验证清单

- [ ] macOS 开发模式与打包安装后的进程归属均正确。
- [ ] 同时打开 Safari、其他使用 WebView 的应用或另一个 Frpc-Desktop 时，不混入其他应用的占用。
- [ ] 页面执行 JavaScript、重绘时，能观察到对应辅助进程的占用变化。
- [ ] WebView 创建、关闭、重新加载及辅助进程重启后，统计持续更新且不重复计入。
- [ ] 启动、停止、重启多个 frpc/cloudflared 实例时，现有统计保持正确。
- [ ] 对比系统进程工具时，先对齐 PID 范围、采样周期、CPU 归一化和内存口径，再判断差异。
- [ ] 验证归属查询失败时的行为，以及 Windows、Linux 的 WebView 覆盖范围。
- [ ] 补全实现后，同步更新中英文界面说明和 README 中的统计范围说明。
