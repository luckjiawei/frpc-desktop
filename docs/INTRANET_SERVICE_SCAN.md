# 内网服务扫描功能设计

## 1. 文档目的

本文档描述 Frpc-Desktop「内网服务扫描」功能的产品目标、交互流程、技术方案、安全边界与实施计划，作为后续开发、评审和测试的依据。

当前版本（2.0.x）已经支持多实例 frpc、TOML / 链接导入、Cloudflare Tunnel 和代理管理，但用户要先知道「内网里有什么服务、跑在哪个 IP 和端口」，才能填写代理表单。典型流程仍是：登录路由器或问同事拿 IP → 在本机用 `netstat` / `nmap` 查端口 → 回到应用手填代理。本功能把这段离线操作收敛到应用内，并直接衔接到代理创建。

## 2. 背景与问题

frpc 的使用前提是知道要暴露的本地服务地址。实际使用中常见的阻塞点：

- 服务部署在 NAS、开发机、虚拟机或容器里，用户只知道「大概在 192.168.1.x」，不确定端口；
- 家庭 / 小型办公网络没有资产清单，路由器 DHCP 列表只有 MAC 和主机名；
- 用户能 `ping` 通但不知道服务是否监听、监听在哪个端口；
- 即使找到端口，还要判断 frp 代理类型（HTTP / TCP / UDP）、远程端口是否冲突，然后逐项填写代理表单；
- 非技术用户不熟悉 `nmap`，也不应该在主力机器上安装额外扫描工具。

因此需要一个**只读、限速、默认关闭、结果不落盘**的轻量扫描器，帮助用户发现「本机所在内网中可连接的 TCP 服务」，并把结果一键转成 frpc 代理配置。

## 3. 目标与非目标

### 3.1 目标

1. 自动识别本机网卡与常用私网网段，用户选择范围即可开始扫描。
2. 在可接受的时间内（典型 /24 网段 < 30 秒）发现开放端口，并识别常见服务类型。
3. 结果实时展示、可筛选、可取消；扫描过程不阻塞 UI，不影响正在运行的 frpc 实例。
4. 从扫描结果直接创建 frpc 代理：自动带入本地 IP、本地端口，并按服务类型推荐代理类型。
5. 全流程遵守安全边界：仅私网、仅 TCP connect、无凭据尝试、无漏洞探测、结果不持久化。

### 3.2 非目标

- 不做端口漏洞扫描、弱口令爆破、目录爆破、Web 漏洞检测；
- 不做公网资产测绘，不允许扫描非私有地址；
- 不做持续监控 / 定时扫描 / 后台常驻探测；
- 不替代专业扫描器（nmap、masscan），不追求 SYN 半开扫描和操作系统指纹；
- 首版不支持 UDP 扫描、IPv6 扫描、mDNS / SSDP 主动发现；
- 不自动创建代理或自动启动实例，所有写操作都需用户确认。

## 4. 用户场景

| 场景 | 用户操作 | 期望结果 |
| --- | --- | --- |
| 暴露 NAS 管理页 | 选择 `192.168.1.0/24`，扫描「常用端口」 | 发现 `192.168.1.20:5000` 为 HTTP 服务，一键创建 http 代理 |
| 暴露开发机 SSH | 只知道开发机大概网段 | 发现 `:22`，识别为 SSH，创建 tcp 代理并分配远程端口 |
| 排查服务是否可达 | 输入单个 IP | 列出该主机所有开放端口与响应时间 |
| 迁移旧代理 | 换新路由器后网段变化 | 重新扫描，按服务名快速定位新 IP |

## 5. 功能概览

```text
实例 / 代理 / 日志 ...
        │
        └── 内网扫描（新页面）
              ├── 扫描范围：网卡网段 / 自定义 CIDR / 单个 IP
              ├── 端口策略：常用 / Web / 数据库 / 自定义
              ├── 实时结果：按主机分组，流式追加
              └── 结果操作：创建代理 / 复制地址 / 导出 CSV
```

入口放在左侧导航「代理」之后，命名「内网扫描」（英文 `Network Scan`）。不在启动时自动扫描，也不在后台定时执行。

## 6. 交互设计

### 6.1 页面结构

沿用现有页面骨架（`src/layout` + 内容区），使用 Element Plus 与 Tailwind，不引入新的设计体系。页面分左右两栏：

- 左栏（宽 320px，固定）：扫描配置卡片
  - 网卡下拉：显示 `名称 · IPv4 · 网段`，默认选中默认路由所在网卡；
  - 扫描范围：`CIDR` 输入框，默认填入该网卡所在 /24；支持单个 IP；
  - 端口策略：多选（常用 / Web / 数据库 / 远程管理 / 自定义端口列表）；
  - 高级选项（折叠）：连接超时（300–3000ms）、并发数（32–512）、反向解析主机名；
  - 主按钮「开始扫描」，扫描中变为「停止」；
  - 提示文案：仅扫描私有网段，结果仅保存在本机内存。
- 右栏：结果区
  - 顶部统计：已扫描主机 / 发现主机 / 开放端口 / 耗时；
  - 进度条：按「已完成探测数 / 总探测数」计算，扫描中实时更新；
  - 结果表格：主机（IP + 主机名）、端口、识别服务、响应时间、操作；
  - 筛选：按服务类型、端口、仅显示已识别服务；
  - 空状态：未扫描 / 无结果 / 已取消，分别使用不同文案和图标。

### 6.2 扫描流程

1. 用户点击「开始扫描」。
2. 前端校验 CIDR、端口和并发参数，弹出一次确认对话框，列明目标网段、主机数、端口数和预计最长时间。
3. 后端解析目标并开始扫描，通过事件流式返回进度与结果。
4. 用户可随时「停止」；停止后保留已发现结果，并标记为「已取消」。
5. 扫描完成后统计信息定格，结果可继续筛选和操作。

### 6.3 结果操作

- **创建代理**：打开现有代理编辑抽屉（复用 `src/views/proxy/index.vue` 的表单），预填：
  - `type`：按服务推荐（HTTP 服务 → `http`，HTTPS → `https`，其余 → `tcp`）；
  - `localIP`：扫描到的主机 IP；
  - `localPort`：扫描到的端口；
  - `name`：`<主机名或 IP>-<服务名>`，去重后追加序号；
  - 远程端口 / 域名留空，由用户确认，避免自动分配造成 frps 侧冲突。
- **复制地址**：复制 `ip:port`。
- **导出 CSV**：列为主机、IP、端口、服务、响应时间；使用系统保存对话框，默认文件名 `frpc-scan-<yyyyMMdd-HHmm>.csv`。

### 6.4 状态与文案

| 状态 | 展示 |
| --- | --- |
| 空闲 | 配置卡片 + 空状态「选择范围后开始扫描」 |
| 校验失败 | 表单下方行内错误，不发起请求 |
| 扫描中 | 进度条、统计数字滚动、结果逐行出现、按钮变为「停止」 |
| 已取消 | 保留结果，顶部标签「已取消」，可重新扫描 |
| 完成无结果 | 空状态「该范围内未发现开放的 TCP 服务」，附排查提示 |
| 后端错误 | ElMessage 错误提示 + 结果区错误态，保留已有结果 |

所有用户可见文案同时写入 `src/lang/zh-CN.ts` 与 `src/lang/en-US.ts`，沿用 frp 术语（代理、访问者、服务端）。

## 7. 技术设计

### 7.1 总体架构

```text
Vue 页面 src/views/scan/index.vue
  └─ Pinia store src/store/scan.ts
       └─ IPC invoke("ipc_send", { path: "scan/startScan", ... })
            └─ src-tauri/src/commands/mod.rs  scan/* 分支
                 └─ src-tauri/src/scan/  扫描引擎（tokio 异步任务）
                      ├─ target.rs      CIDR / 网段展开与校验
                      ├─ ports.rs       端口集合与常用端口表
                      ├─ probe.rs       TCP connect、banner、TLS / HTTP 识别
                      └─ scheduler.rs   并发调度、限速、取消、事件推送
```

扫描完全位于 Rust 侧，前端只负责参数、进度和结果渲染。不新增数据库表，不修改迁移编号。

### 7.2 目标解析

支持三种输入：

- 单个 IPv4：`192.168.1.10`；
- CIDR：`192.168.1.0/24`；
- 起止地址：`192.168.1.10-192.168.1.50`（可选，首版可只做前两种）。

校验规则：

1. 仅允许 RFC 1918 私网（`10/8`、`172.16/12`、`192.168/16`）、链路本地（`169.254/16`，但排除云元数据地址）和回环（`127/8`，仅本机调试）；
2. 拒绝 `0.0.0.0/0`、组播、广播、公网地址和 IPv6；
3. 单次扫描主机数上限 1024，超出时要求缩小范围；
4. 展开后去重，排除网络地址与广播地址。

> 说明：不做「自动发现所有网卡的全部网段」的批量扫描，避免用户误扫公司大网。默认只填当前默认路由网卡的 /24。

### 7.3 端口策略

| 策略 | 端口 | 说明 |
| --- | --- | --- |
| 常用 | 22, 80, 443, 445, 3389, 5900, 8080, 8443 | 默认选中 |
| Web | 80, 443, 3000, 5000, 5173, 8000, 8080, 8081, 8443, 9000 | 开发 / NAS 常见 |
| 数据库 | 3306, 5432, 6379, 27017, 9200, 1433, 1521 | 仅探测可连接性，不尝试登录 |
| 远程管理 | 22, 23, 3389, 5900, 5985, 5986 | — |
| 自定义 | 用户输入 `8000-8010,9000` | 单次最多 256 个端口 |

端口集合在 Rust 侧再次校验和去重；自定义范围展开后同样受 256 上限约束。

### 7.4 扫描引擎

采用 **TCP connect 扫描**：

- 使用 `tokio::net::TcpStream::connect`，不需要管理员权限或 raw socket；
- 每个探测设置独立超时（默认 800ms），超时视为关闭 / 被过滤；
- 不重试，避免放大流量；
- 对同一主机的探测加 0–50ms 随机抖动，避免瞬时突发；
- 通过 `tokio::sync::Semaphore` 控制全局并发（默认 256），可在高级选项中调整；
- 使用 `tokio_util::sync::CancellationToken` 响应停止请求，取消后不再发起新探测，已建立的连接立即关闭。

扫描结果只在内存中聚合，按主机分组；不写数据库、不写日志文件。

### 7.5 服务识别

识别分三层，按成本和准确度递进：

1. **端口映射**：内置端口 → 服务名表（22 SSH、80 HTTP、443 HTTPS、3306 MySQL、5432 PostgreSQL、6379 Redis、3389 RDP、5900 VNC、445 SMB 等）。
2. **协议探测**：
   - HTTP 类端口：发送 `HEAD / HTTP/1.1\r\nHost: <ip>\r\nConnection: close\r\n\r\n`，读取响应头，识别 `Server`、`WWW-Authenticate`、`Location`，并判断是否为 Web 管理页；
   - TLS 端口：发起 TLS 握手（`rustls` / `native-tls`），读取证书主题与 SAN，识别 HTTPS 服务；
   - 其他端口：读取最多 512 字节 banner（500ms 超时），匹配 SSH、FTP、SMTP、MySQL、Redis 等特征前缀。
3. **保守归类**：无法识别时显示「未知服务」，只展示端口和响应时间，不猜测。

识别结果包含：`service`（规范化名称）、`product`（可选，如 `nginx`）、`tls`（是否 TLS）、`confidence`（`high` / `medium` / `low`）。首版不解析 HTML 标题，避免额外请求和误判。

### 7.6 进度与事件

IPC 路由（`src/core/IpcRouter.ts`）：

```ts
SCAN: {
  startScan:      { path: "scan/startScan",      controller: "scanController.startScan" },
  cancelScan:     { path: "scan/cancelScan",     controller: "scanController.cancelScan" },
  getScanStatus:  { path: "scan/getScanStatus",  controller: "scanController.getScanStatus" },
  listInterfaces: { path: "scan/listInterfaces", controller: "scanController.listInterfaces" }
}
```

事件（后端推送，前端在页面挂载时订阅、卸载时移除）：

| 事件 | 载荷 | 频率 |
| --- | --- | --- |
| `scan:progress` | `{ scanId, scanned, total, hostsFound, openPorts, elapsedMs }` | 每 100ms 或每 200 个探测 |
| `scan:result` | `{ scanId, host: { ip, hostname? }, services: [...] }` | 每批最多 20 条，100ms 节流 |
| `scan:finished` | `{ scanId, status: "completed" \| "cancelled" \| "failed", error?, stats }` | 一次 |

后端只允许一个活动扫描任务；重复 `startScan` 返回 `bizCode` 冲突错误。应用退出或页面切换不自动取消扫描，但关闭窗口时随进程结束。

### 7.7 数据结构

```rust
#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct ScanService {
    pub port: u16,
    pub service: String,
    pub product: Option<String>,
    pub tls: bool,
    pub confidence: String,
    pub banner: Option<String>, // 截断到 120 字符，去除控制字符
    pub response_ms: u32,
}

#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct ScanHostResult {
    pub ip: String,
    pub hostname: Option<String>,
    pub services: Vec<ScanService>,
}
```

`banner` 仅用于界面提示，不写入日志、不导出到 CSV（避免泄漏服务指纹中的敏感信息）。

### 7.8 与代理创建的衔接

前端拿到结果后直接打开现有代理抽屉，不新增后端写接口。代理类型推荐规则：

| 识别结果 | 推荐 `type` | 备注 |
| --- | --- | --- |
| HTTP / Web 管理页 | `http` | 需用户填写自定义域名 |
| HTTPS / TLS | `https` | 需证书或 `https2http` 配置，提示用户 |
| SSH / RDP / VNC / SMB | `tcp` | 需确认远程端口 |
| 数据库 | `tcp` | 默认不推荐直接暴露公网，展示安全提示 |
| 未知 | `tcp` | 只预填本地地址与端口 |

创建前校验：同一实例下 `localIP:localPort` 已存在代理时提示重复，不阻止创建（可能是有意多路复用）。

## 8. 安全与合规

内网扫描属于敏感能力，必须默认保守：

1. **范围限制**：后端强制校验私网地址，前端提示不构成安全边界；任何公网、组播、云元数据地址（`169.254.169.254`）直接拒绝。
2. **只读探测**：仅 TCP connect、TLS 握手、HTTP `HEAD /`、banner 读取；不发送登录请求、不提交表单、不访问非根路径。
3. **限速**：全局并发上限 512，单主机并发上限 16，探测间隔抖动；不提供「高速 / 无限制」模式。
4. **明确授权**：首次使用展示一次说明，要求确认「仅扫描你有权管理的网络」；每次扫描前确认目标范围。
5. **结果最小化**：结果仅保存在内存，页面关闭即清空；不写数据库、不上传、不进入应用日志；CSV 由用户主动导出。
6. **敏感信息**：banner 截断并过滤控制字符；日志只记录扫描 ID、目标数量、耗时和错误类型，不记录 banner、主机名或完整结果。
7. **无持久化副作用**：扫描不修改任何实例、代理或配置；不自动创建代理、不自动启动 frpc。
8. **依赖与权限**：仅使用现有 `tokio` / `reqwest` / TLS 依赖，不新增系统权限；Tauri capabilities 不需要新增文件系统或 shell 权限。

## 9. 性能指标

以 /24（254 个可用地址）× 100 个端口 = 25,400 次探测为例：

| 并发 | 超时 | 理论最坏耗时 | 典型耗时（多数端口拒绝） |
| --- | --- | --- | --- |
| 128 | 800ms | ≈ 160s | 25–40s |
| 256（默认） | 800ms | ≈ 80s | 15–25s |
| 512 | 500ms | ≈ 25s | 8–15s |

目标：

- 扫描期间 UI 帧率不受影响，CPU 占用低于单核 20%；
- 事件节流后前端每秒渲染不超过 10 次；
- 1,024 主机 × 256 端口的上限场景下内存占用低于 50MB；
- 取消请求在 500ms 内停止发起新探测。

## 10. 错误处理

| 情况 | 行为 |
| --- | --- |
| CIDR 非法 / 超出私网 | 后端返回 `ApiResponse::fail`，前端行内提示 |
| 主机数或端口数超限 | 拒绝并提示上限 |
| 网卡列表获取失败 | 允许手动输入 CIDR，提示无法自动识别 |
| 扫描中网络切换 / 网卡消失 | 记录失败探测，继续其余目标，结束时汇总 |
| 用户取消 | 返回 `cancelled`，保留已发现结果 |
| 应用退出 | 任务随进程终止，无残留文件 |
| 同时发起第二次扫描 | 返回冲突错误，前端提示「已有扫描进行中」 |

## 11. 测试计划

### 11.1 单元测试（Rust）

- CIDR / 单 IP / 起止地址解析与边界地址排除；
- 私网白名单与公网、元数据地址拒绝；
- 端口集合解析、去重、范围展开与上限；
- 端口 → 服务映射；
- banner 截断、控制字符过滤；
- 取消令牌在调度中的传播。

### 11.2 集成测试

在本机启动临时 TCP / HTTP / TLS 服务（测试端口随机分配），验证：

- 开放端口能被发现，关闭端口不误报；
- HTTP 服务识别为 `http` 并带 `Server` 信息；
- TLS 服务标记 `tls = true`；
- 超时、拒绝、不可达三类错误不导致任务失败；
- 取消后不再产生新结果。

### 11.3 手工回归

- 单网卡 / 多网卡 / VPN 虚拟网卡环境；
- 深色 / 浅色主题，中英文长度；
- 扫描期间切换页面、最小化窗口、启动 frpc 实例；
- 结果表格 500+ 行时的滚动与筛选性能；
- 一键创建代理后表单预填正确、可保存、可启动。

## 13. 风险与开放问题

| 风险 / 问题 | 说明 | 处理 |
| --- | --- | --- |
| 被安全软件拦截 | 部分终端防护会把批量 connect 判为扫描行为 | 首次使用说明、限速、默认只扫 /24；文档写明用途 |
| 用户误扫大网段 | 公司网络可能触发 IDS 告警 | 主机数上限 + 确认对话框 + 默认仅当前网段 |
| 识别准确率 | 非标准端口和自定义协议无法识别 | 显示「未知服务」，不阻塞创建代理；后续可加指纹库 |
| 是否需要 UDP | mDNS、DHCP、部分游戏服务依赖 UDP | 首版不做；如需求明确再评估，UDP 探测误报率更高 |
| 是否持久化历史 | 用户可能想对比两次扫描 | 首版不落库；后续可导出 / 导入 JSON，需先评估敏感数据留存 |
| IPv6 | 家庭网络逐步启用 | 首版不支持，后端显式拒绝并提示 |
| 权限提示 | macOS 本地网络权限、Windows 防火墙 | 文档说明；首次扫描失败时给出系统设置指引 |
