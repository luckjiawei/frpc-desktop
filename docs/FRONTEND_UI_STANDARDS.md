# Frpc-Desktop 前端 UI 开发标准

## 1. 文档目的

本文档用于约束开发者和 AI Agent 对 Frpc-Desktop renderer 界面的新增与修改。目标是在不改变现有产品视觉语言的前提下，保证页面布局、组件选型、交互状态、文案和可维护性一致。

本文档是 UI 实现的默认规范。若需求、设计稿或现有业务行为与本文档冲突，应先说明冲突和影响，确认后再偏离规范，不得自行创建另一套视觉风格。

## 2. 适用范围与依据

适用于 `src/views/`、`src/components/`、`src/layout/`、`src/styles/` 以及 renderer 中所有用户可见内容。

当前 UI 技术基线：

- Vue 3、TypeScript 和 `<script setup lang="ts">`；
- Element Plus 作为表单、按钮、表格、抽屉、弹窗、反馈等交互组件的首选；
- Tailwind CSS 工具类用于常规布局、间距、尺寸和文字样式；
- SCSS 用于公共主题、复杂状态、动画以及无法清晰地由工具类表达的样式；
- Iconify 离线图标作为应用内图标的首选；
- vue-i18n 管理用户可见文案。

现有界面的主要参考实现为：

- 应用骨架与导航：`src/layout/`、`src/styles/layout.scss`；
- 全局主题与章节标题：`src/styles/index.scss`、`src/styles/element.scss`；
- 状态型主页：`src/views/home/index.vue`；
- 长表单页面：`src/views/config/index.vue`；
- 卡片/表格双视图和编辑抽屉：`src/views/proxy/index.vue`；
- 列表、进度与空状态：`src/views/download/index.vue`；
- 特殊深色内容区：`src/views/logger/LogView.vue`。

## 3. 设计原则

1. **延续现有界面。** 优先复用已有页面结构、Element Plus 组件和公共类，不为单个需求引入新的设计体系。
2. **信息优先。** 界面应紧凑、清晰，重点突出连接状态、配置内容和主要操作，避免纯装饰元素抢占空间。
3. **状态完整。** 异步界面必须同时考虑加载、成功、空数据、失败、禁用和处理中状态。
4. **桌面端优先。** 这是 Electron 桌面应用，应适配窗口缩放和中英文长度变化，但不按手机页面重构应用骨架。
5. **危险操作克制。** 删除、重置、覆盖等不可逆操作必须有明确危险语义和二次确认。
6. **一致性高于局部创意。** 新页面应让用户感到它原本就属于本应用。

## 4. 视觉基础

### 4.1 颜色

现有品牌主色为紫色：

| 用途 | 标准值 | 使用方式 |
| --- | --- | --- |
| 主色 | `#5F3BB0` | Element Plus `primary`、主要按钮、链接、选中态 |
| 主色兼容值 | `#5A3DAA` | 现有标题、边框和装饰；新代码优先使用主色变量 |
| 主色浅背景 | `#EBE6F7` / `#EEEBF6` | 菜单选中、章节标题浅底 |
| 页面背景 | `#F3F3F3` | 主内容区背景 |
| 内容背景 | `#FFFFFF` | 卡片、表单容器和空状态容器 |
| 危险色 | `#F56C6C` | 删除、破坏性操作和错误强调 |
| 成功/警告/信息色 | Element Plus 语义色 | 状态反馈，不自行发明近似色 |
| 次要文字 | `#6B7280` 或 Element Plus 次要文字色 | 辅助说明和弱化信息 |

要求：

- 新增界面优先使用 `type="primary|success|warning|danger|info"`、`text-primary`、公共 SCSS 变量或 Element Plus CSS 变量；
- 不得因为单个页面新增一套品牌色或大面积渐变；
- 硬编码颜色仅用于语义明确且局部隔离的场景，例如日志级别或特殊可视化，并应说明原因；
- 文本与背景必须保持清晰对比，不得仅依赖颜色表达状态，需同时提供文字、图标或形状提示。

### 4.2 字体与字号

- 使用全局字体栈，不在页面内加载或指定新的正文字体；
- 页面标题沿用 Breadcrumb：`18px`、粗体；
- 表单章节标题沿用 `.h2`（`16px`）和 `.h3`（`14px`）；
- 正文和表单控件遵循 Element Plus 默认字号；
- 辅助信息通常使用 `12px` 或 `14px`，不得小于 `12px`；
- 数据、版本号和关键状态可加粗，但避免大段粗体；
- 路径、日志或配置片段需要等宽展示时使用系统等宽字体栈。

### 4.3 间距、圆角与阴影

使用现有的紧凑间距体系：

- 应用主内容内边距：`15px`；
- 页面头部与内容间距：`15px`；
- 常规内容容器内边距：`p-4`（`16px`）；
- 紧凑控件间距：`gap-2`（`8px`）；常规分组间距可用 `gap-3` / `gap-4`；
- Element Plus 栅格 gutter 优先使用现有的 `10px` 或 `15px`；
- 卡片沿用 `rounded` 与轻量 `drop-shadow` / `drop-shadow-lg`；
- 不新增夸张大圆角、重阴影、玻璃拟态或发光效果。

间距优先使用 Tailwind 标准档位或现有公共值。除对齐现有固定布局外，避免散落的任意像素值。

### 4.4 图标与动画

- 优先使用已注册的 `IconifyIconOffline` 图标；只有品牌图标等离线库不适合的场景才使用其他资源；
- 图标应与操作语义直接对应，同类操作在不同页面保持同一图标；
- 只有图标、没有文字的按钮必须提供可访问名称和悬浮说明（如 `aria-label`、`title` 或 tooltip）；
- 图标通常跟随文字颜色和组件尺寸，不随意指定新颜色；
- 动画只用于状态变化、载入反馈、导航提示或关键成功反馈；
- 动画应短且不阻塞操作，禁止给普通列表项加入持续运动或大范围入场动画；
- 新增动画需兼容 `prefers-reduced-motion`，减少动态效果时应禁用非必要动画。

## 5. 应用骨架与页面布局

### 5.1 固定骨架

应用采用左侧导航 + 主内容区结构：

- 左侧导航宽 `60px`，高度 `100vh`，白色背景；
- 主内容区宽度为 `calc(100% - 60px)`，高度 `100vh`，背景 `#F3F3F3`，内边距 `15px`；
- 新页面不得绕过 Layout 创建第二套顶栏、侧栏或全屏壳层；
- 特殊沉浸页面如确需突破骨架，必须由需求明确指定。

### 5.2 标准页面结构

路由页面默认使用以下层级：

```vue
<template>
  <div class="main">
    <Breadcrumb>
      <!-- 可选：当前页面工具栏 -->
    </Breadcrumb>
    <div class="app-container-breadcrumb">
      <!-- 页面内容 -->
    </div>
  </div>
</template>
```

- 所有普通路由页必须复用 `Breadcrumb`，标题和图标来自路由元数据；
- 页面级主要操作放在 Breadcrumb 右侧插槽，按“筛选/视图切换 → 次要操作 → 主要操作”排列；
- 工具栏允许换行，窗口变窄时不得互相遮挡或溢出；
- `app-container-breadcrumb` 是默认滚动容器，避免页面内出现多个争抢滚轮的纵向滚动区；
- 内容区右侧需要为滚动条保留空间时，沿用 `pr-2`；
- 普通内容使用白色容器；日志等专业内容区可以使用与语义匹配的局部深色主题，但不得改变全局主题。

### 5.3 响应式与窗口缩放

- 使用 Element Plus 的 `el-row` / `el-col` 或 Flex/Grid 完成布局，不通过绝对定位搭建主结构；
- 表单在空间足够时可双列，窄窗口下应回落为单列；
- 操作区使用 `flex-wrap`，文字不得与图标重叠；
- 表格列根据重要性设置 `min-width`，关键操作列可固定在右侧；
- 长文本使用换行、省略 + tooltip 或可滚动容器，不能撑破页面；
- 至少检查仓库当前 Electron 默认窗口尺寸，并缩窄窗口验证无明显裁切；不得假设始终全屏。

## 6. 组件与交互标准

### 6.1 组件选择

- 按钮、输入、选择、开关、表格、标签、进度、抽屉、弹窗、空状态和消息反馈优先使用 Element Plus；
- 不手写已有的 Element Plus 基础组件，也不新增功能重复的 UI 依赖；
- 重复两次以上、具有独立语义或状态逻辑的 UI 应评估提取到 `src/components/`；
- 页面专用的小片段可以保留在页面中，避免为了抽象而抽象；
- 组件 Props、Emits 和跨层 payload 必须有明确 TypeScript 类型。

### 6.2 按钮与操作层级

- 一个操作区域默认只设置一个视觉最强的主要按钮；
- 提交、保存、启动、导入等主操作使用 `type="primary"`；
- 次要操作使用 `plain`、`link` 或文本按钮；
- 删除使用 `danger` 语义，不使用普通主色伪装危险操作；
- 同组按钮的图标、尺寸、排列方式保持一致；
- 异步提交期间应显示 loading 或禁用，防止重复触发；
- 高频事件按现有做法使用合理防抖，但不能让开关、输入等即时反馈显得迟钝。

### 6.3 表单

- 配置页长表单沿用右对齐标签和稳定标签宽度；抽屉内编辑表单优先使用顶部标签；
- 相关字段用 `.h2` / `.h3` 分节，标题文案必须进入 i18n；
- 必填、格式、范围及跨字段关系都要有校验；错误提示应说明如何修正，不能只显示“错误”；
- 输入框提供准确的 label，placeholder 只用于示例或补充，不代替 label；
- 密码、Token、密钥默认遮挡；不得在界面、日志或错误消息中意外回显；
- 依赖其他选项的字段应条件展示或禁用，并保持已保存数据的兼容性；
- 保存成功使用轻量消息反馈，失败信息需保留足够的排查语义；
- 重置、导入覆盖等操作必须在执行前确认影响。

### 6.4 列表、卡片与表格

- 数据少、强调概览时可使用卡片；字段多、需要比较或批量浏览时使用表格；
- 同一数据支持卡片/表格双视图时，两种视图必须提供等价的核心信息与操作；
- 卡片沿用白底、轻阴影、紫色左边框的现有样式，操作区放在右侧；
- 表格优先使用 `border`、`stripe`、溢出提示和明确列宽；
- 名称或主标识可使用主色加粗；状态使用 `el-tag`、`el-switch` 或明确文字；
- 行操作保持“编辑/主要操作在前，更多菜单在后”，低频或危险操作放入更多菜单；
- 复制操作完成后必须提供成功反馈。

### 6.5 抽屉、对话框与确认

- 字段较多且需要保留列表上下文的编辑流程使用右侧 `el-drawer`；
- 简短确认、提示和少量输入使用 `el-dialog` / `ElMessageBox`；
- 抽屉标题应明确“新增”或“编辑”的对象，底部操作顺序在同类界面中一致；
- 关闭未保存的复杂表单时，应根据数据丢失风险决定是否提示；
- 不使用 `dangerouslyUseHTMLString` 拼接不可信或 renderer 外部输入；确需富文本时保证内容固定或完成转义。

### 6.6 反馈与页面状态

每个异步数据页面都必须实现适用的状态：

- **加载：** 使用 `v-loading`、进度条或按钮 loading，保持布局稳定；
- **空数据：** 使用 `el-empty`，说明当前为空；如用户可以解决，应提供下一步操作；
- **成功：** 保存、复制、导入、删除等明确动作使用 `ElMessage` 等轻量反馈；
- **失败：** 给出用户可理解的信息；可恢复时提供重试或检查入口；
- **处理中：** 下载、启动等耗时操作展示进度或进行中状态，并防止重复执行；
- **禁用：** 说明无法操作的条件，不能只让控件变灰而无上下文。

不要用空白区域代替加载或异常状态，也不要用 `alert()` 等浏览器原生弹窗替代 Element Plus 反馈。

## 7. 文案、国际化与格式

- 所有新增的用户可见文案必须同时加入 `src/lang/en-US.ts` 和 `src/lang/zh-CN.ts`；
- Vue 模板和脚本中通过 `$t()` / `t()` 使用文案，不直接硬编码中文或英文；
- 品牌名、协议名、配置键、动态日志等不应翻译的内容除外；
- 中英文 key 层级和插值参数必须保持一致；
- 沿用现有 frp/frpc、代理、Visitor、服务端等术语，不创造同义说法；
- 按钮使用简短动词，确认框明确操作对象和后果；
- 日期、大小、时长和数字的展示在同一页面保持一致；
- 必须检查较长英文文案，避免固定宽度导致截断。

## 8. 可访问性与桌面体验

- 可点击的非原生元素必须支持键盘操作和清晰焦点态；能用 `el-button` 时不要用普通 `div` 模拟按钮；
- 图标按钮必须有可访问名称；图片必须有有意义的 `alt`，纯装饰图片使用空 `alt`；
- 表单控件必须有关联 label，错误不能只通过颜色表达；
- 不移除 Element Plus 默认焦点轮廓，新增样式不得遮盖焦点态；
- 正文、日志、地址、错误详情等用户可能复制的内容应允许选中，不能受全局禁选样式影响；
- hover 只能作为增强，核心信息和操作不能只在 hover 时出现；
- 外部链接必须通过现有安全 IPC 打开，不直接在 renderer 中调用系统能力；
- 在 macOS、Windows、Linux 上避免依赖单一平台字体、滚动条宽度或快捷键。

## 9. 样式与代码组织

- 常规布局优先使用现有 Tailwind 工具类；公共视觉规则放到 `src/styles/`；页面独有复杂样式使用 `<style scoped lang="scss">`；
- 使用 `@/` 导入 renderer 文件；
- 不使用大量 `!important` 覆盖组件库，必要时先检查 Element Plus Props、插槽和 CSS 变量；
- 修改 Element Plus 全局主题统一在 `src/styles/element.scss` 完成；
- 可复用的色彩和尺寸不得在多个新文件中重复硬编码，应复用现有 class/CSS 变量，或在范围明确时补充设计 token；
- scoped 样式修改子组件时谨慎使用 `:deep()`，选择器应尽量局部；
- 禁止在模板中堆积复杂内联 `style`；动态值除外；
- 不编辑 `dist/`、`dist-electron/`、`release/` 或 `node_modules/` 中的样式和资源。

## 10. Agent 执行规则

Agent 处理任何 UI 任务时必须遵循以下顺序：

1. 阅读本文档以及将要修改的相邻页面、公共组件和样式；
2. 识别可复用的页面骨架、组件、图标、i18n key 和状态处理方式；
3. 在实现前明确主要操作、危险操作，以及 loading / empty / error / disabled 等状态；
4. 只做需求范围内的 UI 变更，不顺带重做其他页面或升级依赖；
5. 新增用户文案时同步更新中英文翻译；
6. 完成后运行 `npm run lint` 和 `npm run build`；
7. 在开发应用中检查受影响流程，并报告实际检查的窗口尺寸、状态和未验证项。

Agent 不得：

- 仅凭通用“现代化 UI”偏好改掉现有紫色主题、应用骨架或组件体系；
- 为一个页面引入新的 UI 框架、图标库、字体或状态管理方式；
- 用硬编码文案、静态假数据或仅截图可见的效果替代真实业务状态；
- 在没有需求依据时扩大为全站重构或大范围格式化；
- 忽略失败、空数据、长文本、窄窗口及中英文切换场景；
- 为追求视觉效果降低信息可读性、键盘可用性或操作安全性。

## 11. UI 交付检查清单

提交 UI 变更前逐项确认：

- [ ] 页面使用现有 Layout、Breadcrumb、主色、间距和卡片风格；
- [ ] 主要、次要、危险操作的视觉层级正确；
- [ ] loading、empty、error、success、disabled 和 processing 状态已按需实现；
- [ ] 异步操作不会被重复提交，删除/覆盖操作有确认；
- [ ] 新增文案已同时加入英文和简体中文翻译；
- [ ] 长英文、长路径、错误文本和列表溢出不会破坏布局；
- [ ] 窄窗口和默认窗口尺寸下无明显遮挡或不可达内容；
- [ ] 图标按钮、表单 label、键盘焦点和颜色对比可用；
- [ ] 未输出或回显 Token、密码、密钥、本地敏感路径等信息；
- [ ] 没有新增重复组件、无必要依赖、散落主题色或大范围样式覆盖；
- [ ] `npm run lint` 和 `npm run build` 通过；
- [ ] 已手动检查受影响的 Electron 页面流程，或明确报告未检查原因。
